# 订单与服务配置

## 购买与履约

选择套餐 → 填写联系邮箱和账号信息 → 检查资格并报价 → 创建订单 → 付款 → 跟踪兑换结果。

游客可以购买；联系邮箱用于通知和登录后认领订单，充值账号从账号信息中读取。订单号与邮箱本身不能作为查单凭证。钱包充值和余额抵扣需要登录，消费余额与邀请收益分开记账。

普通套餐按后台固定售价出售；升级套餐根据 AICDK 返回的成本、有效汇率和后台利润规则报价。正式环境需先确认并开启升级利润规则。报价过期后重新检查账号，已创建订单的金额保持不变。

默认普通充值价格：Go ¥48、Plus ¥135、Pro 100 ¥678、Pro 200 ¥1,210、Pro 500 ¥3,260。
升级默认按成本加价 30%（成本 × 1.30），再结合服务费、最低毛利、最低售价和向上取整规则计算；此比例未扣除渠道费用与邀请返现，也不代表固定售价套餐的实际利润率。

已有数据库运行 `bun run db:update-commercial-policy` 应用本次调价和 3% / 4% / 5% / 6% 返佣比例。该命令会更新上述五档普通套餐、四档升级加价比例及返佣比例，并写入审计记录；保留返佣等级标识、名称、门槛、其他设置及已有订单、报价、佣金快照。`db:seed` 仍只补齐缺失数据。

账号 Session 仅用于检查与兑换授权，不写入本站数据库或浏览器持久存储。收款成功后由 worker 提交兑换并同步结果；需要新 Session 时在原订单内更新。结果不确定的订单需先核对上游，避免重复执行。

## 优惠码与带券链接

后台「优惠码管理」（`coupons:read` / `coupons:write`）支持固定金额立减与百分比折扣（可设最高减免上限）、最低订单门槛、有效期、总名额、单买家限次、仅首单与需登录限制；适用范围可选全部套餐、仅普通充值、仅差价升级或指定套餐。钱包充值订单不支持使用优惠码。

- **带券链接与全站差价展示**：任意页面支持 `?coupon=CODE` 或 `?promo=CODE` 自动校验并保存 30 天（后点击的有效优惠码覆盖前值）。生效期间顶部显示优惠条，首页、套餐卡片、对比页、详情页展示划线原价、券后价与已省差价；SEO 结构化数据保留标准原价。结算页可在验证账号前后随时输入、更换或移除优惠码，无需重新粘贴 ChatGPT Session。
- **金额底线与升级成本保护**：优惠后订单应付金额最低为 `¥0.01`（`1` 分，不产生 0 元单）。动态差价升级订单默认启用保本底线（`cost`），按报价快照中的上游成本与汇率限制最大减免额；也可配置保留最低毛利（`min_profit`）或不设底线（`none`）。
- **名额并发锁与超时释放**：下单时对优惠码行加锁校验，写入 `orders` 的 `list_amount`、`discount_amount`、`coupon_id`、`coupon_code`、`coupon_snapshot` 及 `coupon_redemptions` 占用记录。未发起渠道支付且超过 30 分钟未付款的占座订单由新请求与 worker 自动取消并释放名额；已拉起支付的订单保留占座直至确认结果。主动取消待付订单或确认失败后完成退款也会释放对应名额。
- **存量数据库升级**：新库 `bun run db:init` 已包含优惠码表结构；存量数据库先执行 `prisma/updates/add-coupons.sql`，再运行 `bun run db:verify` 与 `bun run db:seed` 补齐运营/客服角色的优惠码权限。

## 人工确认兑换结果

后台「订单管理」中，处理中的套餐订单（包括结果不确定、需要进一步处理、需要新 Session）提供「人工处理」。管理员核对上游兑换记录和账号实际结果后，选择「已核实成功」或「已核实失败」，填写核对依据并确认提交。操作要求订单写权限及近期身份验证。

- 确认成功会完成订单、消耗关联兑换码、按订单原规则结算返佣，并发送订单通知。
- 确认失败会停止兑换同步，之后可使用「处理退款」单独办理退款；不会自动退钱或释放兑换码。确认失败前应在上游确认原兑换不会继续执行。
- 处理人、时间、原状态和核对备注永久保留在「处理记录」，备注仅后台可见。已登记的人工结论不能直接覆盖；重复提交同一结论不会重复结算。
- 自动提交与人工处理通过数据库锁协调；打开弹窗后订单状态发生变化时，需要刷新并重新核对。人工处理停止后续同步，已经发出的查询若返回相反的最终结果，会标记「结果冲突待核对」，保留人工结论并写入审计日志。处理退款或再次兑换前，须先核对该冲突。

## 服务配置

在后台「支付与服务」填写连接信息，再到「网站设置」选择启用的渠道。

| 服务               | 必填配置                                                           |
| ------------------ | ------------------------------------------------------------------ |
| AICDK              | API 地址、应用 Key，兑换及换码需要相应 `redeem:*` 权限             |
| XorPay             | App ID、Secret                                                     |
| GMPay              | 兼容 `GMWalletApp/gmpay-edge` Merchant API 的网关 URL、PID、Secret |
| 易支付             | 选择 v1 或 v2，填写对应商户及签名密钥                              |
| Resend / Sendflare | API Key、经过验证的发件地址                                        |
| SMTP               | 发信地址、服务器与 TLS 凭证                                        |
| Turnstile          | Site Key、Secret Key，站点域名与 `APP_URL` 一致                    |

保存会生成配置版本，订单继续使用创建时绑定的版本。留空密钥保留原值。GMPay 有在途订单时，使用新 PID 切换收款并保留旧凭证，避免原地更换 Secret 导致回调验签失败。

支付回调地址由服务端传给网关：`/api/payments/notify/{provider}/{configRevision}`。只有服务端验签并核对金额后才确认收款，浏览器跳转不改变付款状态。

## 取消与退款

未发起渠道支付的待付订单可取消，余额抵扣退回钱包并释放库存。支付或兑换结果不确定时先人工核对。

确认失败的套餐订单可全额退钱包，或渠道款原路退、余额抵扣退钱包。XorPay 支持自动原路退款；其他渠道由管理员实际退款后登记并填写备注。自动退款超时进入待核实状态，核实前不要重复退款。游客退钱包前需验证邮箱认领订单。

## 账号与权限

用户通过邮箱验证码注册，可添加 OPAQUE 密码、Passkey 和 TOTP。添加 Passkey 会开启二步验证；有 Passkey 时不能关闭。敏感操作要求近期完成身份验证，不提供恢复码。

后台内置客服、运营、财务角色并支持自定义权限。所有者由 `admin:bootstrap` 创建。服务端检查操作权限，关键操作保存业务审计日志。
