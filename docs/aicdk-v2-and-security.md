# AICDK v2 接入与卡密安全

本次接入以本机 AICDK 仓库 `99403827d6b7a0443ee6c413869335ac8d80ee3e` 的
`internal/platform/openapi_public.md`、`account_eligibility.go`、
`redemption.go`、`idempotency.go` 和 `internal/codeformat/code.go` 为依据。
修改范围为 GetCodex Plus；AICDK 服务和内网 HTTP 支持保持原样。

## 接口与购买流程

| 阶段           | 新版接口                                                                   | 本站处理                                                                                                            |
| -------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 账号检查与报价 | `POST /api/v1/account-checks`                                              | 仅提交完整 Session，不查询或预留卡密。核对账号、具体套餐的 `eligible`、币种与报价。                                 |
| 用户确认订单   | `POST /api/v1/redemptions/previews`，`POST /api/v1/redemptions/preflights` | 锁定一张库存并校验实际兑换业务、套餐、账号及成本，只有 `ready` 才保存加密授权。余额和库存随下单事务一起提交或回滚。 |
| 收款后履约     | `POST /api/v1/redemptions`                                                 | 先记录提交尝试，再发送固定的客户请求 ID、预检令牌和幂等键。202 只代表受理。                                         |
| 超时恢复       | `GET /api/v1/redemptions?client_request_id=…&limit=2`                      | 仅接受唯一且与本地订单身份、套餐、业务、价格匹配的结果；存在歧义时停止推进。                                        |
| 状态同步       | `GET /api/v1/redemptions/{id}`                                             | 保存上游 ID 和版本。仅 `completed` 完成订单；`uncertain`、`requires_action` 保留订单和库存，继续核对。              |
| 更新凭据       | `PUT /api/v1/redemptions/{id}/account-session`                             | 使用原订单和确定性幂等键。已存在上游订单时不重新分配库存或创建另一笔兑换。                                          |

卡密绑定的 redemption preflight 是实际兑换授权，和付款前的 account check 分开。
账号检查结果不可以直接用于提交兑换。`pricing` 响应即使带有令牌，也不能作为 ready 授权。

本站现有的取消操作只处理尚未发起支付的本地待付订单，不调用新版上游取消接口；
`can_resubmit` 也不会触发自动新建兑换。失败订单由管理员核实后选择退回钱包或原路退款；XorPay 支持自动原路退款，其他渠道由管理员手动退款并登记备注。

前端保留完整 Session 的额外字段以符合 AICDK 契约，仅在当前结算组件内存中暂存，
在创建订单时再次提交。成功创建、报价失效、页面离开或组件卸载时清除；
没有 Session 的新报价不能绕过确认阶段。Session 不进入本站数据库、网址、日志、
localStorage 或 sessionStorage。用户刷新页面后需重新检查账号。

## 套餐和金额

- 站内 `pro5`、`pro20`、`promax` 分别映射到 `pro_100`、`pro_200`、`pro_500`。
- 指定目标的 `eligible=null` 代表未确定，不能借用其他套餐的 true 结果放行。
- 升级成本读取 `amount_minor`、`currency`、`currency_decimals`，不再读取
  `payment_usd_cents`。缺失精度按 ISO 币种确定，显式精度不一致时拒绝。
- JPY 零位、KWD 三位等精度都参与整数金额计算；未知币种不按 USD 回退。
- 手动换算率只适用于 USD。其他币种从相应的 `<币种>_CNY` 缓存读取，
  首次遇到未缓存币种时登记刷新任务，由 worker 更新，就绪前暂不报价。
- 订单确认使用报价中的汇率和利润参数快照再次核对。实际成本上升导致售价超过原报价时
  回滚创建，不擅自提高原订单金额。上游变更币种或目标时同样拒绝。
- 普通订阅继续使用本站固定售价，上游仅检查适用性和兑换授权。

## 幂等与异常恢复

`client_request_id` 始终使用本站订单 ID。提交幂等键为
`<订单ID>-v<fulfillment_attempt>`，提交前持久化 `submission_attempted=true`。

发生超时、断网、非 JSON 或异常响应时，保留原令牌与尝试编号，先查询原订单；
未查到时只能按原请求体和原幂等键重放，即使令牌已超过本地有效期。
不能用新令牌或新键强行重试一个结果不确定的请求。

本地尚未提交的过期授权，以及明确拒绝且再次查询确认未受理的请求，才会转为
`needs_session`。新版源码把部分过期或失效预检映射为 `OPERATION_NOT_READY` /
`NOT_FOUND`，不只处理旧的 `PREFLIGHT_EXPIRED`。
仅在这个已确认边界上刷新预检并递增尝试编号，原客户请求 ID 保持不变。

读取订单时检查版本，拒绝旧版本以及同版本的矛盾状态；人工处理状态按非终态展示。
任务结束时还核对本地订单是否已被用户恢复，避免旧 worker 覆盖新的任务唤醒。

## 本站防泄漏措施

1. **存储用途隔离。** 卡密和预检令牌使用 `v2:` 格式的 AES-256-GCM 密文，
   AAD 分别绑定 `inventory:<库存ID>`、`preflight:<报价ID>`。
   运行时不回退到旧的通用用途；通用加解密函数也要求显式用途参数。
2. **卡密去重。** 按 AICDK owned-code 规则规范化大小写、前缀和分隔符，
   使用 HMAC 指纹去重。数据库中的无密钥 SHA-256 指纹被替换。
   API、管理列表和审计记录不返回完整卡密、密文或指纹。兑换码管理列表只显示尾四位掩码；导入批次、备注、国家切换及库存开关见[批次管理](inventory-batches.md)。
3. **最少留存。** AICDK 受理并绑定上游订单后就清除本地预检令牌；
   取消、完成、退款和可清理的过期报价也清除令牌。库存卡密仍按既有业务需要加密留存。
4. **错误边界。** 上游响应通过结构校验并限制大小。错误码只能来自固定集合；
   不保存上游原始错误文本。API 验证错误与未知异常采用固定文案，
   日志不记录异常名称、请求体、SQL 参数或供应商返回正文。
5. **浏览器边界。** 全局 GA/GTM 脚本及相关依赖已移除；保留本站购买阶段统计。
   CSP 使用每个响应独立的 nonce，约束脚本、外部连接、iframe、表单和嵌入。
   Turnstile 使用 nonce，Ant Design 所需内联样式保留。
   页面与 API 使用 no-store / no-referrer，正式站点配置 HSTS。
6. **后台输入。** 导入需要现有 `products:write` 权限、最近十分钟验证及请求限流。
   导入成功或取消时清空表单，关闭时销毁输入组件；禁用拼写检查和自动更正。
   现有服务配置修改权限及重新登录要求继续保留。

## 升级已有部署

以下描述的是 AICDK v2 的历史数据转换。当前版本已采用 Prisma，`db:migrate` 不再自动执行重加密。首次接管和适用的兼容桥见 [Prisma 数据库运行手册](prisma-migration.md)；未达到密文/认证前置条件的更早版本须先用相应历史版本完成升级。

1. 备份数据库及当前 `ENCRYPTION_KEY`、`BETTER_AUTH_SECRET`。本次迁移不轮换密钥。
2. 停止 Web 和 worker，避免旧代码继续写入旧格式或与迁移混跑。
3. 在采用 Prisma 之前的对应 AICDK v2 版本中执行其数据库升级入口。历史升级会：
   - 添加报价流程版本、预检有效期、上游状态/版本和提交尝试标记；
   - 保留旧报价的版本、原配置 ID、兑换 ID、客户请求 ID、尝试编号和订单金额；
   - 在一个事务中重加密旧卡密、旧预检令牌，并重建规范化的 HMAC 去重指纹；
   - 将既有处理中订单保守标记为可能已提交，先恢复原请求。
4. 解密失败或出现同一卡密不同展示格式的重复记录时，迁移回滚。
   在受控环境核对重复库存及关联订单，处理冲突后重跑，不直接丢弃已绑定订单的记录。
5. 构建并启动新版 Web 和 worker。核对专用 AICDK 应用密钥具备 `redeem:*`，
   使读取、POST 提交及 PUT 更新 Session 均可用。
6. 对原有处理中订单先观察恢复结果，再进行真实小额联调。

迁移可重复执行。旧代码不认识新版密文，代码回滚不能简单覆盖部署文件；
需要在停止流量后配套恢复备份及状态核对，避免重放已完成交易。

## 验证与边界

数据库契约测试在独立 `_test` 数据库的临时 schema 中运行，通过模拟新版 HTTP 响应覆盖：
无库存账号检查、资格未知、目标映射、原币种定价、并发下单、价格上涨回滚、
超时恢复、确定失败恢复、PUT 更新、外来/过期结果拒绝、凭据迁移及响应脱敏。
浏览器测试覆盖实际生产构建的 CSP、登录、结算、订单、后台导入和密钥只写。

这不是生产流量审计，也不证明历史上从未泄漏。真实 AICDK、收款渠道和账号的完整联调
需要部署环境的有效凭据与真实测试账号；模拟测试不会替代它。

按既定设计，内网 HTTP 以及后台可配置 AICDK 地址保留。服务配置写权限、服务器、
数据库与加密密钥、AICDK 实例和内网是信任边界。被授权更换服务地址的人能决定后续
凭据的接收方；仅限制卡密不进前端不能消除此高权限风险。
反向代理/APM 请求体采集、数据库参数日志、备份访问、浏览器扩展和主机权限属于
仓库之外的运行环境，本次未检查或修改。
