# 风控

风控使用内嵌 GoRules ZEN 引擎。规则保存在 `src/server/risk/limits.json` 和 `decisions.json`，随代码维护；无需外部规则服务，也不向 GoRules 发送业务数据。

## 执行规则

- 请求按浏览器、用户、邮箱、充值目标、可信 IP 或全局额度限流；需同时满足适用的各维度限制。
- 登录与购买可分别启用 Turnstile，服务端校验令牌、场景与站点域名。
- 同一用户、联系邮箱或充值目标有至少 5 个未支付订单时，暂停新订单。
- 同一收款账户关联至少 3 个用户，或账号注册未满 24 小时时，提现进入人工审核。
- 自邀不返现；启用仅首单规则时检查已成功交付的订单。

限流拒绝仍保留计数；下单失败回滚库存和余额。引擎或必要信息不可用时拒绝请求。风控不替代登录权限、支付验签和业务状态检查。

## 配置与记录

本项目部署在网关后。登录、风控和支付共用 `src/server/client-ip.ts` 中的配置与 Better Auth IP 解析函数，统一读取网关提供的 `X-Forwarded-For`，不再使用 `TRUST_PROXY` 或 `X-Real-IP`。

遵循当前 Better Auth 默认行为：接受单个有效地址，未配置可信代理列表时不接受多地址链；IPv4 映射地址转换为 IPv4，IPv6 按 /64 网段归一化。生产环境缺失或无效的地址不参与 IP 维度限流，支付参数使用空字符串；开发和测试环境沿用 Better Auth 的 `127.0.0.1` 回退。

关联标识使用按用途隔离的 HMAC，不在风控记录中保存邮箱、IP、收款账号或 Session 明文。后台「风控记录」展示命中原因和规则版本，需要 `audit:read` 权限。

worker 定期清理超过 30 天的风控记录和过期计数。部署时保留 ZEN 所需的平台原生依赖，Web 与 worker 使用相同代码版本。
