# 兑换码批次与国家切换

后台使用两级导航。「商品与兑换」下包含商品管理、兑换码管理、导入批次及订单管理；资金、用户权限与系统设置分别归组。页面选择写入 URL hash，刷新及浏览器前进／后退可恢复当前页面，菜单按现有权限过滤。

## 操作方式

1. 在「导入批次」导入兑换码，选择本站商品，填写批次名称、AICDK 商品、国家和备注。可粘贴每行一码，也可选择 AICDK 导出的 CSV。
2. CSV 默认以文件名命名批次，可自行修改。格式是单列 `code` 表头，支持 UTF-8 BOM、CRLF、引号转义；每次最多 500 个，文件不超过 256 KB。多余列、空行、坏引号及非法兑换码会拒绝导入，不把表头当作库存。
3. 默认开启「导入后切换为当前供货批次」。取消后，批次以禁用状态保存，可稍后启用。
4. 启用批次会把同一站内商品的其他批次禁用，并设为唯一供货来源。例如为本站 Plus 导入土耳其与美国两个 AICDK 商品的兑换码后，启用土耳其批次即可切换新订单的供货国家。
5. 禁用当前批次或耗尽库存后，新订单缺货；不会自动回退到更贵的国家或历史库存。可用开关重新启用其他有库存的批次。
6. 「编辑备注」可修改批次名称和备注。导入时间、操作人、新增数量、重复数量保持原始记录；当前各状态数量反映实时库存，逐码更换会使批次内的历史记录增加。
7. 「查看兑换码」进入该批次的明细，可筛选、分页、批量启用／停用未占用码，或更换一张未占用码。更换会新增记录并停用旧码，保留旧指纹与审计记录。

AICDK 导出的单列 CSV 没有商品和国家字段，后台填写的商品、国家用于辨认批次，不会修改上游兑换码绑定。实际业务、套餐、账号与成本仍通过原有 AICDK 预览／预检校验；更换国家应导入对应国家的新批次。

## 数据与并发规则

- 新增 `inventory_batches`，记录商品、批次名、上游商品标记、国家、备注、启用状态、导入人及导入数量；库存保存批次 ID、单码启用状态与入库时间，商品保存当前批次 ID。
- 卡密继续按库存 ID 绑定 AAD 加密，并按规范化 HMAC 指纹跨商品、跨批次去重。重复码不会移动归属或重新启用。全重复的导入仍留下批次记录，但批次禁用，不切换当前供货来源。
- 库存列表只返回尾四位掩码、记录 ID 和管理信息，不返回完整卡密、密文或指纹；导入和更换输入在完成或关闭后销毁。
- 读取需要 `products:read`；导入、批次切换、备注编辑及逐码操作需要 `products:write`、最近验证、同源校验与限流。
- 下单事务先对商品加 `FOR SHARE` 锁，读取当前批次，再沿用库存行 `FOR UPDATE SKIP LOCKED` 分配。切换批次对同一商品加 `FOR UPDATE` 锁，等已经开始的分配事务完成后再切换。多个并发切换因此按商品串行提交。
- 批次禁用不会改变已占用码、已用码及订单。取消订单后释放的旧码仍受批次选择与开关限制。恢复 Session、上游同步及退款沿用原订单绑定。
- 逐码操作对库存行加锁，并同时检查状态及非取消订单关联；遇到占用或已使用记录整笔操作回滚。换码去重冲突也会回滚，旧码保留原状态。
- 升级前无批次的库存继续使用原库存池。首次选定批次后只从选定批次分配，原库存仍保留可查；不伪造历史批次或原始导入人。

## 部署与验证

部署新代码前运行 `bun run db:migrate` 应用 `20261114050000_inventory_management`，随后重启 Web 和 worker。迁移是增量添加，不修改已有卡密或订单绑定。

回归覆盖 CSV 格式与数量限制、规范化去重、批次备注、零新增导入、分页筛选、国家切换、禁用与耗尽后不回退、切换时仍在分配的订单、逐码替换回滚、生产构建下的导入表单与二级导航。数据库测试在独立 `_test` 数据库的临时 schema 中运行。
