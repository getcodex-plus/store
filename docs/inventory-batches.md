# 兑换码与导入批次

## 从 getcodex.plus 进货

1. 在上游获取 Dujiao-Next 下游 API 凭证并为上游钱包充值；在本站「支付与服务 → Dujiao-Next 进货」填写站点地址和凭证并启用。
2. 在「商品管理」读取上游目录，选择本地充值套餐与上游**自动发卡**商品的 SKU，保存映射。仅映射每行交付一个普通充值兑换码的 SKU；手动交付、地区专属半价码不走此入口。一个 SKU 在同一配置版本中只能映射到一个套餐。
3. 确认 SKU、数量（1–500）和上游售价，再提交进货。按上游下单时的价格从上游钱包扣款；本站零售价不会自动改变。此操作需要 `products:write`、`integrations:read`、`integrations:write` 和近期身份验证。
4. worker 用同一 `downstream_order_no` 提交或重试，拿到上游单号后只查单，不传客户 Session，不需要回调。上游确认已交付且数量、卡密校验通过后，整批加密入库，可在「导入批次」核对。采购单固定原映射和凭证版本，更换配置后需为新采购重新绑定。

「待交付」不等于已入库。扣款明确失败不会自动再次下单；交付数量不符、重复卡密或上游退款会转入「需人工核对」，不会部分入库。请先核对上游订单号和钱包流水，不要以新单号反复采购。

### 付款后按单采购（无需备货）

在「商品管理」选择本地套餐和上游自动发卡 SKU，勾选「付款后按单采购」并保存映射。旧映射默认仍是手动进货。要关闭自动采购，重新选择 SKU、取消勾选并保存；已创建的订单继续使用原 SKU 和凭证版本。

- 本模式只出售普通渠道的套餐。报价时先核验账号资格；创建订单不占本地库存、不采购。确认渠道收款或钱包全额扣款后，worker 才按上游现价为本单购买 **1 个码**。未付、取消及钱包充值订单不触发采购。
- 到货的码直接锁给原订单，不可再售。本站不保存买家的 Session，也不把它发给供货方；买家在订单页看到到货提示后，再提交同一账号的 Session 完成预检与兑换，不需再次付款。
- 在采购记录中按原单号核对。上游明确拒单后可按失败订单处理；交付不符、供货结果长期不确定会转人工核对，不自动退款。使用「重新同步原单」沿用原采购标识，不要另开采购单。

已付款订单充值失败不会直接释放卡密。买家发起[原单免费补充](orders-and-services.md#已付款原单免费补充)时，系统先核对原兑换和旧卡；只有确认可用且已改用备用卡，旧卡才回库供下一单使用。

## 导入与管理

在后台「商品与兑换 → 导入批次」选择商品，填写名称与备注，然后粘贴每行一码或上传 AICDK CSV。CSV 使用单列 `code` 表头，每次最多 500 个码、256 KB。

所有已启用批次共同供货。停用批次只影响新订单，已创建订单继续使用绑定的兑换码。兑换码管理支持筛选、分页与批量启停；已占用或已使用的码不能修改。

卡密加密存储，列表只显示掩码。系统按规范化指纹跨商品、跨批次去重，重复导入不会移动归属或重新启用。操作需要商品管理权限与近期身份验证。

## 上游换码

「更换」先向 AICDK 检查资格，再请求新码；成功后旧码永久失效，新码沿用本站商品、批次和启用设置。完整新码由服务端加密保存，不返回浏览器。

网络错误或结果不确定时使用「核对换码」继续原请求。显示「需到 AICDK 核对」时，先在上游处理再导入可用新码；待核对旧码保持锁定，不参与售卖。

## Plus 半价库存

普通 Plus 商品可选择「Plus 50% Discount」渠道，并填写两位国家代码，如 `us`、`jp`。每批只导入同一地区的码。

账号符合优惠资格且有匹配库存时，系统按上游成本选择地区；否则使用普通渠道。优惠资格、地区和内部成本不向客户展示，客户售价不变。付款后履约和 Session 更新保持原订单的渠道与卡密。
