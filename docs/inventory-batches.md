# 兑换码与导入批次

后台使用两级导航。「商品与兑换」下包含商品管理、兑换码管理、导入批次及订单管理；资金、用户权限与系统设置分别归组。页面选择写入 URL hash，刷新及浏览器前进／后退可恢复当前页面，菜单按现有权限过滤。

## 操作方式

1. 在「导入批次」导入兑换码，选择本站商品，填写批次名称和备注。不再单独填写上游商品或国家／地区；来源、采购成本等信息可写入备注。充值和升级商品使用相同的批次规则。
2. 支持粘贴每行一码，或通过「File」选择／拖入 AICDK 导出的 CSV。文件在浏览器内解析，确认保存时才提交兑换码。显示文件名、识别数量、大小，支持移除、重新选择和错误提示。
3. CSV 默认以文件名命名批次，可自行修改。格式是单列 `code` 表头，支持 UTF-8 BOM、CRLF、引号转义；每次最多 500 个，文件不超过 256 KB。多余列、空行、坏引号及非法兑换码会拒绝导入。
4. 默认开启「导入后启用批次」。所有已启用批次共同供货，导入或启用一个批次不会禁用其他批次。同一国家的两次补货可以同时启用；系统不按国家分组或互斥。
5. 批次开关独立生效。禁用后只停止该批次参与新订单，其他已启用批次仍可分配；已有订单继续使用原兑换码。某批次耗尽后可继续使用其他已启用批次的可用码。
6. 「编辑备注」可修改批次名称和备注。导入时间、操作人、新增数量、重复数量保留原始记录；当前库存数量反映实时状态，换码会增加历史记录。
7. 「查看兑换码」进入该批次的明细，可筛选、分页、批量启用／停用未占用码。列表区分可用、已停用、已占用、已使用（Used）；已占用和已使用码不能修改。Used 反映本站履约记录，不代表主动同步了其他渠道的使用情况。

## 上游换码

「更换」只需确认，不接受手动输入新码。服务端使用外部应用的 `redeem:*` 权限调用 `POST /replacements/previews` 检查资格，再调用 `POST /replacements`。仅上游允许更换的未使用、未过期自有码可用；旧码永久失效，新码保留上游商品、批次和有效期，本地沿用商品、导入批次和原单码启用状态。

- 换码前持库存行锁检查订单关联，持久化请求标识及 AICDK 配置版本，并将旧码停用。上游调用结束前后都不能分配旧码。
- 新码仅返回一次，收到后立即绑定新的库存 ID 加密保存；完整码不返回浏览器。旧指纹保留，防止重新导入旧码。
- 重复点击使用同一持久化幂等键和配置版本。已完成的请求直接返回本地结果，不再次换码。
- 网络错误或结果不确定时显示「换码待核对」，只能用「核对换码」继续原请求；不会重新预检已失效的旧码，也不会生成新幂等键。
- 如果上游已换码但重放不再返回完整新码，或结果与预检不一致，记录上游新码 ID 并显示「需到 AICDK 核对」。旧码保持锁定，需要在 AICDK 处理后导入可用的新码；本站无法恢复上游只返回一次的密钥。

## 数据与并发规则

- `inventory_batches` 记录商品、名称、备注、启用状态、导入人和导入数量；库存保存批次 ID、单码开关及入库时间。商品不再保存唯一当前批次。
- 卡密按库存 ID 绑定 AAD 加密，按规范化 HMAC 指纹跨商品、跨批次去重。重复码不会移动归属或重新启用。全重复的导入仍留下禁用批次记录，不影响其他批次。
- 库存列表只返回尾四位掩码、记录 ID 和管理信息，不返回完整卡密、密文或指纹。导入输入在完成或关闭后销毁。
- 读取需要 `products:read`；导入、批次启停、备注编辑及逐码操作需要 `products:write`、最近验证、同源校验与限流。
- 下单先对商品加 `FOR SHARE` 锁，再从全部已启用批次及无批次的历史库存中，按库存行 `FOR UPDATE SKIP LOCKED` 分配。单码也必须启用，且不在换码流程中。批次开关对商品加 `FOR UPDATE` 锁，等待已开始的分配事务结束后生效。
- 批次禁用不改变已占用码、已使用码或订单。取消后释放的旧码仍受单码及批次开关限制。恢复 Session、上游同步及退款沿用原订单绑定。
- 逐码操作检查状态及未取消订单关联；遇到占用、已使用或换码锁定记录，整笔操作回滚。

## 部署与验证

部署前停止 Web 和 worker，运行 `bun run db:migrate`，随后重启。除了批次管理迁移，还需应用 `20261114060000_independent_inventory_batches` 和 `20261114070000_inventory_replacements`。前者删除原唯一批次选择、上游商品和国家字段，保留各批次现有开关状态；后者保存换码请求与核对结果。不修改原有订单绑定或卡密。

回归覆盖 CSV 格式与数量限制、文件错误恢复与移除重选、规范化去重、批次备注、零新增导入、分页筛选、充值与升级多批次共同供货、独立禁用、并发分配、历史库存、Used 状态、上游换码、重复请求、超时及一次性新码丢失处理。数据库测试在独立 `_test` 数据库的临时 schema 中运行；上游接口使用模拟响应，不调用真实换码服务。
