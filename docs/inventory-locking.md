# 卡密锁定与并发审查

审查日期：2026-11-14。范围为本站正式模式的库存导入、报价、下单、取消、履约和退款路径，以及真实 PostgreSQL 集成测试；不包含生产库历史数据核查或上游服务内部实现。

## 锁定过程

1. 账号检查、生成报价不占用卡密。
2. 确认下单开启数据库事务，锁住用户（游客按浏览器摘要加事务锁）和报价，先处理重复请求、已有订单。
3. `reserveInventory` 在目标商品中寻找可用卡，或已过期且没有未取消订单关联的旧预留卡。所有候选都必须没有未取消订单关联。
4. `SELECT ... FOR UPDATE OF i SKIP LOCKED` 锁住选中的库存行，跳过其他事务正在操作的卡。立即在同一事务内写入 `reserved`、`reserved_until = NULL`。
5. 持锁调用上游预览和预检，校验账号、目标套餐、价格，然后绑定报价、创建订单、扣除余额并提交。任一步失败均回滚本站的库存、订单和余额变更。
6. 提交后数据库行锁释放，持久化的 `reserved` 状态和订单关联继续阻止重复分配。订单创建后的卡没有自动到期时间；报价的 9 分钟有效期不等于订单库存的锁定时间。

多个 Web 实例必须使用同一个 PostgreSQL 数据库。这里依赖数据库事务和行锁，不依赖单个进程的内存锁。

## 释放与消费

| 情况                                     | 库存行为                                             |
| ---------------------------------------- | ---------------------------------------------------- |
| 下单预检失败、价格不匹配、事务回滚       | 本次预留回滚，卡可以再次分配                         |
| 未发起支付的未付款订单取消               | 只有仍为 `reserved` 且没有其他未取消订单关联时才释放 |
| 已发起支付、支付结果待核对               | 禁止直接取消，不释放                                 |
| 处理中、需要更新 Session、上游响应不确定 | 保持占用，继续原订单                                 |
| 成功完成                                 | 标记 `consumed`                                      |
| 已确认失败或退款                         | 不自动回收卡，避免上游已使用但本地再次出售           |
| 旧的限时预留过期且没有未取消订单         | 下次分配时按需回收选中的卡                           |

取消后保留历史报价与卡的关联是正常现象；重复取消会直接返回，不会释放后来分配给其他订单的卡。卡密导入另有规范化指纹唯一约束，防止同一卡的不同展示格式作为多份库存导入。

## 本次修复

- **旧版报价绕过库存互斥：** 原先只有 `flowVersion === 2` 才进入选卡与锁定步骤。旧报价可能仍引用已经被回收和重新分配的卡。现在正式模式只允许当前版本报价创建新订单；已存在订单仍按原有幂等逻辑返回。
- **回收阻塞：** 原先在选卡前批量更新所有商品的过期预留，可能先等待其他事务持有的行锁，导致后面的 `SKIP LOCKED` 无法及时执行。现在只锁定并回收目标商品中选中的一行。
- **状态与关联不一致时重复分配：** 原先可用卡仅依据 `status = 'available'` 选择。现在同时检查未取消订单关联，即使状态被误改，也拒绝重新分配。
- **历史冲突释放：** 取消订单时增加库存状态和其他订单关联条件，避免把其他订单仍在使用的卡释放。

没有修改数据库结构。这些订单归属保护由应用事务执行；数据库已有卡密指纹唯一约束，但没有跨 `quotes`、`orders` 的“一张卡只能关联一个未取消订单”硬约束。维护脚本和后续新增分配入口必须遵守同一锁定协议，不能直接写入绑定关系绕过它。

## 验证

`src/server/aicdk-flow.test.ts` 新增独立商品、独立买家、真实数据库连接的场景：

- 两个不同用户抢最后一张卡：第一个请求暂停在上游预检期间，第二个请求必须缺货，不能扣款或绑定库存。
- 12 个不同用户抢 3 张卡：仅 3 个订单成功，卡 ID 全部不同。
- 同商品及其他商品存在被锁住的过期卡时，仍能选中未锁定的卡。
- 未付款、处理中、需 Session、成功、失败、退款订单关联的卡，均不能因过期时间或错误的可用状态再次分配。
- 旧报价引用已分配卡时拒绝新建订单。
- 预检失败回滚后，另一用户可以成功使用同一张卡。
- 游客取消后卡可重新分配，重复取消及重复下单不会释放新归属。
- 历史重复绑定中，取消一个订单不会释放另一个订单仍占用的卡。

运行：

```sh
TEST_DATABASE_URL=postgresql://getgpt@127.0.0.1:55479/getgpt_test bun run test
bun run check
```

目前预检仍在持锁事务内进行，单事务预算为 100 秒，单实例数据库连接池上限为 10。慢上游会延长锁和连接的占用，其他买家可能暂时看到缺货或等待连接；这是仍需关注的容量边界，本次未改变为跨事务租约流程。
