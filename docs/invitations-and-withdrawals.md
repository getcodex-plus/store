# 邀请等级与收益提现

## 邀请等级

| 等级       | 有效邀请人数 | 新订单返现比例 |
| ---------- | ------------ | -------------- |
| 邀请新星   | 0–4 人       | 2%             |
| 分享达人   | 5–19 人      | 3%             |
| 推荐官     | 20–49 人     | 4%             |
| 邀请合伙人 | 50 人及以上  | 5%             |

后台「网站设置 → 邀请返现」可调整名称、人数门槛和比例，比例上限 9%。第一级门槛必须为 0，其余逐级提高。
仅直接邀请有奖励，没有下级分佣。默认好友每笔符合条件的成功交付套餐订单都返现，复购也有奖励。后台可开启「仅首笔成功交付订单返现」限制为首单；结算天数沿用网站设置。

有效邀请来自成功交付、佣金已结算、未冲回的套餐订单，按订单联系邮箱去重；同一联系邮箱重复购买只计一人，游客也计入。
注册数单独展示，不作为升级条件。自邀限制始终执行；开启仅首单时，继续按用户、联系邮箱和充值账号检查历史成功订单。
佣金以订单总实付（含充值余额抵扣）乘以比例、按整数分向下取整。钱包充值本身不返现。

每笔订单创建时保存等级对应返现比例、结算期和首单规则。升级、退款降级、后台改比例都只影响新订单，已有订单不重算。
新等级在达到门槛的佣金结算后生效。退款冲回后重新统计有效邀请，可能降级；游客认领订单不改变计数。

## 两类资金分账

- 消费余额：钱包充值、订单退款；只用于站内购买。
- 邀请收益：待结算、已结算；只有已结算部分产生提现额度。

```text
可提现 = max(0, 已结算邀请收益 − 已打款金额 − 申请中冻结金额)
冻结金额 = 待审核申请 + 打款处理中申请
冲回差额 = max(0, 已打款金额 + 冻结金额 − 已结算邀请收益)
```

例如：消费余额 ¥1,000、已结算收益 ¥500、已提现 ¥100、申请中冻结 ¥50、待结算收益 ¥80，则最多再申请 ¥350。
消费余额和待结算收益不会把上限提高到 ¥1,430。冻结和已提现都按申请总额计算，包含从申请金额内扣除的手续费。
冲回导致缺口时阻止新提现和打款登记；新的结算收益先覆盖缺口，管理员可以拒绝未打款的申请释放冻结。

## 提现渠道、起提金额与手续费

后台「网站设置 → 提现渠道」分别配置支付宝、微信，以及 USDT 的 Ethereum、Tron、BNB Smart Chain、Polygon 四个网络。
每一项都有独立开关、最低起提金额、比例手续费和固定手续费；USDT 另有总开关。提现开关与购买付款方式独立。
开启 USDT 时必须至少启用一个网络。前台仅展示开放的渠道与网络，服务端在创建申请的同一事务内重新检查开关、最低金额和费用。
关闭渠道只停止新申请；既有申请仍可重试查询、受理、打款或拒绝。

```text
手续费 = 四舍五入到分(申请金额 × 手续费比例) + 固定手续费
预计到账净额 = 申请金额 − 手续费
```

最低起提与固定手续费均以人民币元填写，数据库以整数分保存，比例以基点保存（100 基点 = 1%）。
两个手续费字段都可设为 0；每个起提金额必须确保扣费后仍有正数到账。
例如申请 ¥100，费率 2%、固定费 ¥1，则冻结 ¥100、手续费 ¥3、预计到账 ¥97；USDT 按 ¥97 净额确认折算数量。
拒绝申请释放完整的 ¥100，不收取手续费。

迁移时各渠道起提金额继承原网站最低提现设置（新站默认 ¥50），手续费默认 0。
配置后六套规则互不影响，不再受旧全局最低金额限制。
申请保存实际费率、固定费与手续费快照；后台改价不改变旧单。
如果用户打开表单后费用发生变化，服务端拒绝旧报价，前台刷新费用并要求重新确认，之后才能再次提交。

## 提现申请表

从「我的钱包」或「邀请有礼」进入，按以下顺序填写：

1. 只读额度摘要：本次最多可提现、申请中冻结、最低提现；明确充值和退款余额不可提现。
2. 收款方式：已开放的支付宝、微信或 USDT。
3. USDT 专属网络：Ethereum / Tron / BNB Smart Chain / Polygon，仅显示已开启网络，切换后重新校验最低起提与手续费。
4. 提现金额（人民币元）：支持两位小数和「全部提现」，前后端均验证所选渠道最低金额与邀请额度上限，数据库使用整数分。
5. 收款人姓名：用于人工核对，加密保存。
6. 收款账号：支付宝账号、可联系收款的微信号，或完整 USDT 地址，加密保存并检查对应网络的地址格式。
7. 提交确认：展示冻结总额、手续费规则、手续费金额与预计到账净额，勾选确认后提交。

USDT 由管理员在打款前与申请人确认净额的折算数量，后台提供汇率 API 参考换算，没有自动换汇、链上校验或自动代付，不会把人民币金额直接当成 USDT 数量。
前端网络格式检查不等于验证地址所有权或链上可达性。同一个 0x 地址不能判断接收网络；打款前还需核对收款平台支持的链与 USDT 资产。
微信同样通过人工核对收款。
不承诺固定到账时长。记录显示申请金额、收款信息、状态、处理说明、实际打款金额与流水号。

## 审核流程

```text
待审核（冻结） → 受理 / 打款处理中（继续冻结） → 已打款（计入已提现）
待审核 或 打款处理中 → 拒绝（释放冻结，填写原因）
```

受理时锁定处理管理员，处理中的申请仅受理人可登记打款或拒绝。先人工转账成功，再登记已打款。
USDT 审核窗口按本单净额 ÷ USDT/CNY 参考汇率显示转账数量，保留 6 位小数，展示来源、数据日期与获取时间。
直接获取 Currency API 的 USDT/CNY 数据，不将 USDT 与 USD 视为固定等价；与商品定价的 USD/CNY 缓存分开。
可刷新参考数量，登记结果时可点击填入，并在实际打款后核对修改；刷新不会覆盖手动填写的实际到账数量。
服务器复用后台汇率刷新任务，缓存为空时尝试即时获取，默认每小时检查更新；数据来自按日发布的参考价，不承诺实时成交价。
刷新失败只保留仍有效的缓存并明确提示；超过有效期不再提供估算，但仍可按已确认的实际数量登记打款。
登记打款必须提供渠道流水号或链上交易哈希；USDT 还必须记录实际到账数量（最多 6 位小数）。
同一方式和网络的流水号不可重复使用。人民币方式实际打款额等于申请金额减去本单手续费；USDT 记录按本单人民币净额折算的实际到账数量。
处理人、时间及操作审计持久保存，拒绝原因与打款结果向申请人展示。历史申请缺少姓名时由管理员核实原始收款信息。

服务端按用户行锁串行处理申请和审核，重新核对邀请账本，佣金行锁与冲回互斥。相同请求键和参数只冻结一次；
相同请求键换金额、收款方式、姓名、账号或网络会拒绝。充值钱包完全不参与提现额度计算。
申请与后台打款审核继续要求近期登录和原有权限校验。

## 上线与验证

当前版本已采用 Prisma，首次接管已有数据库按 [数据库运行手册](prisma-migration.md) 执行。后续发布先执行 `bun run db:migrate`，再启动新版本服务。全新库显式执行 `bun run db:seed`，初始化邀请等级 2% / 3% / 4% / 5%、每笔返佣和默认提现渠道。
`20261114010000_recurring_referral_rewards` 迁移将已有站点的「仅首笔」开关关闭，新建订单采用每笔返佣；历史订单保留原规则快照，不补发历史佣金。迁移完成后，管理员仍可调整开关。
`20261114030000_lower_referral_rates` 将仍使用旧默认比例 3% / 5% / 7% / 9% 的四档配置调整为 2% / 3% / 4% / 5%，保留等级名称、人数门槛和其他设置；未配置等级的旧站点补齐新默认等级。已自定义比例的站点保持原配置，可在后台手动调整。历史订单（含未支付订单）的比例和佣金记录不变。
提现信息、处理中状态及费用字段已经包含在 Prisma 基线中；旧版升级保留历史订单比例、佣金和提现记录，旧申请手续费为 0。重复迁移或 seed 不覆盖已配置等级、渠道开关、起提金额和手续费。

验证覆盖等级边界、有效邀请去重和游客认领、订单比例快照、消费余额隔离、并发提现、请求重试、审核互斥、拒绝释放、
凭证登记、四个 USDT 网络、渠道开关、独立起提金额、手续费舍入与快照、费用变更确认、汇率换算与缓存失效，以及冲回拦截。
真实支付渠道与人工打款需要上线时按实际运营方式核对。
